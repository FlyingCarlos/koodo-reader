# Koodo Translation Agent

本地 Python 翻译后台，Agent Runtime 为 **OpenAI Agents SDK 0.24.0**。
已接入 PDF 文本提取、章节与整本任务、ChatGPT 订阅授权、本地术语工具、段落翻译、独立审校、定点修订和原书伴随双语包导出。
入口包括 CLI、原阅读器右侧“阅读选项”中的“翻译与双语”折叠区域，以及 PDF 书架右键菜单的“整本翻译…”。

## 在阅读器中使用

1. 在 `https://koodoreader.localhost` 打开有文字层的 PDF，打开右侧“阅读选项”，点击“视图模式”下方的“翻译与双语”标题展开控件。
2. 首次点击“提取本书”，将浏览器书库中的 PDF 副本交给本机后台。若浏览器不能读取，可选择原始 PDF。
3. 通过原生目录或页码选择章节，面板跟随当前阅读位置。选择订阅支持的模型，点击“翻译当前章节”。开启“显示英中对照”。
4. 译文分批出现；只有翻译和独立审校均通过的段落才计入“已审校”。可暂停/继续，关闭页面不影响后台任务。
5. 章节正文全部审校通过后，后台自动恢复该章所有已检测表格页，映射全部就绪才标记章节完成。旧译文可在整本窗口点击“恢复已有译文表格”，复用中文与原订阅模型补齐表格；无表格、仅需加粗或特殊字体的页面仍可点击“恢复本页格式”。
6. 需要顺序补齐全书时，点击面板或 PDF 书架右键菜单中的“整本翻译…”。共用对话框提供新章节模型、章/段进度、章节列表、已译章节表格页进度、开始、暂停、继续、已有译文表格恢复及当前进度导出；关闭窗口不影响后台执行。
7. 排版异常时，在同一区域点击“重新识别排版”，检查当前页与相邻页并按需扩展跨页范围；只调整完整区块的展示，不重译正文。待确认或失败后仍可手动重试。
8. 书架中已有已审校译文的 PDF 显示“有译文”，全书完成显示“已全译”；点击标识可直接打开同一窗口并导出。提取完成或只有初稿的书不标记。

“翻译与双语”初始收起，仅在 PDF 中显示，控件直接放在原生侧栏内并继承菜单主题；阅读区域没有独立的悬浮入口或任务浮层面板。再次点击标题可收起控件，已开启的双语显示和后台任务继续运行。重新展开后读取当前任务状态；需要暂停时使用“暂停翻译”。

英文在左、中文在右，直接嵌入原生 PDF 页面的 iframe。左侧保留原 PDF、文本层、链接和坐标，
右侧按原页显示译文；滚动模式共用原阅读器的滚动区域，页高取两侧较高的一侧。
阅读区域不足 560px 的滚动模式，在同一页面内改为原 PDF 在上、中文在下，保持原生缩放。
原生目录、页码、跳转返回、搜索、书签、选中菜单和笔记继续使用已有组件，双语开关不会卸载 Viewer。
英文高亮保持原 PDF 坐标；中文高亮使用带版本的段落文字锚点，仍通过原生选中菜单和笔记编辑器操作。
同一页与缩放下的正文、列表、表格使用统一正文字号，标题和图注保留层级，过长译文顺延而不逐段缩小。
旧中文笔记可跨样式片段或表格单元格恢复，无需数据库迁移；中文引文变更时拒绝错位恢复；关闭双语后英文批注数据仍使用原格式。PDF 文字重排模式保持原行为，
当前双语显示使用 PDF 原版式。架构和验证边界见 [PDF 翻译集成](../docs/pdf-translation.md)。

Node 服务自动管理 loopback `3017` 上的 Python 子进程，浏览器通过同源 `/api/translation/`
访问。重启前台服务会同时重启后台，运行中的章节重新排队并复用已保存阶段；主动暂停的章节不自动恢复。
同一章节绑定原模型和术语快照，重复提交返回同一任务，避免覆盖译文。

PDF 提取使用 PyMuPDF，保留原文、段落 ID、物理页、坐标与章节映射；有书签时使用主章节，
否则按十页分组。去掉小字号页边文字、合并可判定的跨页段落，并把拼接图片瓦片合成插图。
章节通过多个来源区块合批复用已有 Agent 工作流，面板分别显示段落和批次进度。源文件上限 128 MB / 3,000 页。

当前限制：扫描 PDF 不做 OCR；复杂多栏、表格、公式及字体连字可能提取不完整，需对照原 PDF。
代码与图片保留原样，图片里的文字不翻译。暂无人工修订界面或跨章节上下文检索；
术语快照以推理工程技术书为首批预设。`needs_review` 会明确显示待复核，不宣称完成。

## 整本队列与双语包

整本任务由 `BookQueue` 持久化到同一 SQLite 的 `book_tasks`，复用现有单一章节 consumer，
按目录顺序处理含可翻译文字的章节。已完成章节沿用既有正文与模型；旧完成章节缺少已检测
表格页映射时，先重新排队恢复再向后推进。新建章节使用整本任务
选择的模型，既有未完成任务仍保留其原模型和输入。首次明确开始整本任务会继续既有未完成
章节；失败、额度不足或待复核会停止后续推进。暂停保留当前阶段，服务重启恢复未完成任务，
主动暂停保持暂停；`needs_review` 不会被继续操作静默重译或标成完成。

所有可翻译章节及其已检测表格页完成后自动生成私有 `books/<book-id>/bilingual.koodo.zip`；也可随时在界面
手动导出当前进度。版本 1 包包含 manifest、字节不变的 `source.pdf`、`document.json`、
`chapters/<chapter-id>.json` 及已有来源/译文格式元数据，manifest 标记 `completed` 或
`partial`，封面引用原 PDF 第 1 页。只有正文和全部已检测表格页映射均就绪才标记 `completed`；
`table_presentation` 的 `total` 与 `completed` 统计全书已检测表格的页数，不是表格对象数。
仅需字体样式的无表格页仍可手动恢复；导出不发起模型请求，也不自动补齐格式。
包不包含凭据、SQLite、Agent 私有输入及完整审校过程，格式文件会去除 `job_id`。
区块 ID 和文字偏移保持不变；原生笔记与高亮另由原阅读器备份。书架保留一个原书条目。
当前只实现导出，尚无双语包导入或直接打开 ZIP 的界面；完整格式说明见
[PDF 翻译集成](../docs/pdf-translation.md)。

读取章节优先使用签名匹配的包内章节，其次使用 `reading-<chapter-id>.json`，否则从当前
任务重建。当前读取签名为版本 5，旧派生 ZIP 与快照会失效一次以反映来源结构、数学识别、
视觉分组及表格就绪状态，
原文和既有中文不变。签名查询 SQLite 章节/作业修订号，并检查文档及格式文件时间戳与长度；等长文字
更新和重启排队也能失效旧缓存。损坏的派生包或快照回退到任务数据。SQLite 仍是运行与恢复的
权威存储，快照不取代它。导出在生成前后检查章节签名，遇到持续更新则提示重试。

## 多段合批与目录输入

此前章节已按最多 12 段、6,000 源字符合批，输入 schema 上限为 20 段，并非每行发起一次 API 请求。
当前默认 `BatchBudget` 最多 96 段、20,000 源字符；同时按 UTF-8 字节保守估算输入、中文输出和
审校上下文，预算分别为 6,000、6,000、14,000 tokens，输入包含 1,500 tokens 的共享提示、schema、
工具与术语开销预留。这不是模型专用 tokenizer，也不是模型上下文上限的保证。不可再分的旧区块
可能超过软估算并独占一批，仍须通过输入的 20,000 源字符硬校验。

每批仍经过翻译、独立审校及必要修订；一次工作流批次可包含术语工具回合等多次模型请求，不能把
批次数直接当成 API 请求数。`batch_count`、`completed_batches` 与段落完成数量分别记录。
恢复时只重新合并连续且尚无 `job_id` 的批次；已经创建作业的输入与指纹保持不变，包括失败后重试
的批次。新批次持久化 `source_mode=compact-toc-v1`，不修改原 `document.json` 或来源 ID。

目录识别要求同页至少三条重复点状引导线条目及共同的页码右边缘，支持数字和罗马数字印刷页码。
仅在新批次的模型输入中将符合条件的目录条目化为 `标题\t印刷页码`，保护最终制表符和页码；若
已有受保护字面量无法保留，则使用原文。原提取文字、译文缓存身份和已有作业的输入保持不变。
显示时使用来源目录元数据，无需为修正旧目录版式重新调用模型；细节见下一节。

## 代码不翻译与附加来源结构

代码块必须保留原文，注释、字符串及输出也不翻译。私有书籍目录中的附加
`source-structure-v1.json` 当前内容版本为 3，通过来源行、等宽字体标记、`SourceCodePro`
等字体名及代码/版面启发式识别代码。`prepare_book` 只生成读取和规划视图，将检测到的
代码 ID 从新翻译/审校批次和正文进度统计中排除，不改写原 `document.json`、源 PDF 或
既有 accepted 产物。旧作业记录与输入冻结；含新识别代码的未完成批次改建为正文新作业，
旧记录与产物仍保留。其余旧作业使用原输入恢复，旧完成作业直接复用。进度分母、已审校正文数可能因此下降，原已审校产物仍保留。

前端按来源行重建代码的缩进、空行和换行，使用可横向滚动的等宽 `pre`/`code`。
旧提取中跨页合并的公式与代码按实际来源页显示，保留规范 ID 和 UTF-16 文字片段偏移；
提取遗漏的来源代码行使用稳定派生 ID 展示，不回写原提取数据。提示框使用实际图标裁片
与已有中文，矢量表格底图不参与提示框渲染。格式模型仅接收既有中文与非代码来源样式、
表格和公式元数据，通过精确引文锚点恢复格式及行内公式位置，不重译正文。
代码识别并非所有书籍的保证；扫描 PDF 不做 OCR，左侧 PDF 仍是核对依据。

## 格式恢复与缓存

来源格式是私有书籍目录中的附加 `source-format-v1.json`，逐页译文映射为
`page-format-NNNN.json`。不修改 `document.json`、书籍 ID、提取版本、区块 ID 或源 PDF。
来源相邻的单行正文可在显示时组成连续段落，各区块的精确中文文字与身份保持不变。

`ChapterQueue` 在全部翻译作业完成后，逐页恢复该章已检测表格，再标记章节 `completed`。
格式阶段继续使用原章节任务、原批次和原模型，摘要的 `phase=formatting` 表示正文已完成、
仍在恢复表格。失败、额度不足、暂停和重启继续使用同一队列与持久化逐页作业指针，跳过
`ready` 页，不重译 accepted 正文；主动暂停仍保持暂停。

`POST /api/translation/books/{book_id}/tables/repair` 只重新排队正文全部审校通过且缺少表格
映射的章节，不创建整本翻译任务。整本窗口显示“已译章节表格：x / y 页已恢复”并提供
“恢复已有译文表格”；这里的统计仅覆盖正文已全部审校通过的章节，与 manifest 的全书
表格页统计范围不同。操作发送既有翻译更新事件，阅读器的渲染签名也包含任务状态，重试时
可立即更新页头的待恢复、恢复中或失败提示。无表格的样式恢复保留单页手动入口。

队列补齐会改变原章节任务的状态和修订号，原翻译作业的输入、模型和已审校产物保持不变。

格式 Agent 沿用本应用自己的订阅授权、章节所选模型和 Agents SDK，只返回已有译文的精确引文，
由程序验证来源标识、允许区块和单元格完整覆盖，拒绝改写、遗漏、重叠或外来 ID，再生成 UTF-16
偏移。前端生成 `strong`、`em`、等宽/衬线片段和真实 `table`/`th`/`td`，不接受模型 HTML。
来源格式和现有中文共同生成指纹；读取时若不匹配，旧映射失效为 `pending`。没有有效格式时仍可
阅读普通译文；表格文字覆盖校验失败也回退到普通译文。

来源页格式读取会为已有缓存页派生附加 `toc_entries`，目录区块不再进入旧的正文合并组。
此元数据不参与已有样式映射指纹或格式 Agent 输入，因此既有加粗、表格映射仍可复用。中文目录
按标题、引导线、印刷页码三个连续 UTF-16 片段呈现，保留每一个原字符；字面点线以零字号保留，
由可伸缩的 CSS 点线显示，页码用右对齐列。标题可换行，缩进及标题/页码加粗来自源页。
译文后缀与来源印刷页码不符时回退普通译文；不会按 PDF 物理页改写印刷页码。旧中文笔记仍能
跨这些片段恢复到同一原生编辑器，无需迁移数据库。

格式请求复用同一生产 worker 的执行锁和 `worker.lock`，不要针对同一状态目录另起 worker。
模型调用前先写入任务指针，已完成的格式阶段可从缓存恢复而无需再次请求。与翻译阶段一样，
模型响应尚未保存即崩溃时仍可能重发，不承诺计费层面恰好一次。

## 来源排版识别与完整边界

`layout_sources.py` 直接从原 PDF 提取有独立身份的来源行、原 Unicode、物理页、坐标和字体，
用本地规则识别明确的完整多行数学结构；歧义公式或相邻页的代码延续进入 `LayoutQueue`。
新章节翻译前审计来源歧义，开启双语的侧栏也可自动检查当前页；自动结果按来源哈希和
`VERSION` 复用，包含当前页的已识别范围不重复调用模型。未解决的同签名结果也不自动反复
请求；手动“重新识别排版”始终可在既有任务结束后重新运行。

`GET /api/translation/books/{book_id}/layout?page=N` 读取状态，`POST` 接收 `page`、`model`
和可选 `automatic`。初始窗口为前页、当前页、后页。Agent 接收原页截图和来源行/坐标，
仅返回公式、代码、段落的行引用及前后扩展/不确定标记，不翻译或改写内容。代码含注释、输出，
公式保留原符号；程序控制几何、字体与笔记锚点。模型要求排除表格、图像、提示框，
这些内容继续使用既有专用渲染；不支持的结构可保留待确认。

程序检查来源行存在、唯一、顺序、连续物理页以及规范区块完整覆盖；旧分组的边界也须完整。
必要时每次向前/后扩展两页后重识别，最多 18 页、10 轮。代码、公式可跨页和章节，段落
重组仅限同页完整规范区块。无效结果带校验原因重试一次；仍有歧义、重试失败或边界超限
标记 `needs_confirmation`，保持此前排版，不应用局部结果。自动任务排队时先等待识别；
失败或待确认时以 `layout_requires_confirmation` 停止该章正文翻译及后续推进，不清除已有译文。

任务存入同一 SQLite 的 `layout_tasks`，重启将运行任务重新排队；沿用应用订阅、Agents SDK、
同一生产 consumer、`operation_lock` 和 `worker.lock`，不得另起生产 worker 或 API Key 回退。
本地缓存 `source-math-v1.json` 和经原子替换应用的 `layout-overrides-v1.json` 位于私有书籍目录。
源 PDF、`document.json` 不变；读取签名包含这些附加文件，伴随导出也携带展示元数据并去除
私有作业 ID。已返回但尚未保存的模型阶段仍可能因崩溃重发。

公式使用原 Unicode、坐标行偏移与数学回退字体展示，不保证嵌入 Type3 字体或任意分式复刻。
完整段落复用 accepted 中文、样式及行内公式锚点；规范区块 ID、UTF-16 笔记路径、旧派生
代码别名保留，新来源行 ID 独立于分组。没有迁移旧笔记。详见
[PDF 翻译集成](../docs/pdf-translation.md#完整逻辑区块的排版识别)。

## 安装和运行

在本目录执行，使用 `uv.lock` 固定依赖：

```sh
uv sync --locked --python 3.12
uv run koodo-translate login
```

将打印的授权地址在 **Edge** 打开。确认名称为 `Koodo Reader Translation`，由用户完成
ChatGPT 登录和订阅使用授权。回调只监听 `127.0.0.1`，默认等待五分钟；超时可重新运行。
本工具不读取 Codex 的登录文件，也不回退到环境中的 API Key。

```sh
uv run koodo-translate status
uv run koodo-translate models
uv run koodo-translate translate --input examples/sample.json --model <models返回的slug>
uv run koodo-translate jobs
uv run koodo-translate show <job-id>
uv run koodo-translate translate --input examples/sample.json --model <原model> --resume <job-id>
```

示例是本项目编写的两段技术说明，不读取现有书库。实际请求会把输入文本、相关术语与审校
上下文发送到 OpenAI；使用用户授权的 ChatGPT 计划额度或可用 credits，并受账号、应用和
模型访问限制。模型列表不是计费成功的证明，必须实际完成推理后才能确认接入可用。

## 执行与数据

1. 翻译 Agent 先调用具名本地工具 `book.lookup_glossary`，返回带源段落 ID 的中文译文。
2. 程序检查段落顺序、完整 ID 集合和显式保护的代码/公式字面量。
3. 独立审校 Agent 返回包含原文证据、位置、严重程度和建议的问题列表。
4. 有问题时只修订受影响段落，再审一次；仍有问题标记 `needs_review`，保留所有版本。

初版独立审校指角色和上下文独立，默认使用用户选择的同一模型，不意味着错误独立或质量
已获人工认证。结构检查也不能证明段落内部不存在语义漏译。

每个成功阶段写入 SQLite。失败后从已保存阶段继续，恢复必须使用相同输入、术语表、模型和
工作流版本。额度错误暂停任务；流中断不会被当作成功，不会自动改走 API Key 计费。
在收到模型结果但尚未保存时崩溃，恢复可能重新请求这一阶段；不承诺计费层面恰好执行一次。

目录权限为 `0700`，新建凭据和数据文件权限为 `0600`，凭据以原子替换写入并序列化刷新。
初版只维护一个当前账号，尚无账号切换或登出界面；可在 ChatGPT 设置中管理或撤销该应用的
访问。数据不位于 Git、`build/` 或浏览器存储中。`--state-dir <目录>` 可为测试指定独立目录。
SDK 托管 tracing 已关闭，诊断输出不打印凭据或 OAuth 错误响应正文。

## 订阅请求约束

- 仅使用官方 `https://api.openai.com/v1/responses`，OAuth 请求由本机后台处理。
- 模型请求必须 `store=false`、`stream=true`，必须接收到 `response.completed` 才能接受输出。
- 使用命名空间中的本地函数工具，不依赖托管 File Search、Code Interpreter 或 MCP。
- 上下文、阶段状态及长期记忆由本机维护；不使用服务端 conversation 或 previous-response ID。
- 单次输入硬限制为 96 个段落、共 20,000 源字符，并使用上述上下文软预算；每阶段限 6 个 Agent 回合和 180 秒。
- 原文作为待翻译数据处理，不执行书内指令。工具当前只读取传入的术语，不访问任意文件。
