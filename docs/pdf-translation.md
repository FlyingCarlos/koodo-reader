# 原生 PDF 阅读器的翻译扩展

## 集成边界

`Reader` 保留整个原阅读器组件树；`TranslationPanel` 只显示任务状态和开关。不得再通过提前 `return` 一个新阅读器隐藏原生功能。

PDF 的入口是右侧“阅读选项” → “翻译与双语”，位于“视图模式”正下方，由 `SettingPanel` 管理展开状态，初始收起。点击标题在原生侧栏内展开或收起 `TranslationPanel`；提取、模型选择、章节任务、格式恢复和“显示英中对照”沿用原控件。标题按钮提供 `aria-expanded`、`aria-controls` 和键盘焦点样式。侧栏负责滚动及主题颜色，阅读区域不再有独立的悬浮入口或浮层面板。

`Viewer` 在创建原生 `PdfRender` 后调用 `attachPdfTranslation`。适配器不修改打包的 Kookit 库，也不替换原生目录、搜索、进度、PageWidget、PDF canvas、文本层、链接和批注画布。原文保持 PDF 版式，右侧译文使用同一原生页面文档；原生文档选区监听器和 PopupMenu/PopupBox 因而处理两侧的选择。

双语模式的 `comparisonViewport` 使用当前可用宽度，为锁定的目录、设置或右侧停靠面板预留空间；`Viewer` 和原生仿真背景共用该区域。原 PDF 等比适配左栏可用宽度，不直接把原生高度适配结果再减半。canvas、文本层、链接和批注继续共用原生坐标体系。滚动模式按 PDF 物理页组织两栏，页高容纳两侧内容；原阅读器的滚动、渲染与位置记录继续负责翻页。翻页模式保留原生导航，过长的单页译文可在右侧滚动。

桌面中文段落先匹配原生文本层的文字，再用来源坐标选择附近的匹配；找不到文字时回退到来源区块范围。字号参考源页正文主字号及实际 PDF 显示比例；没有格式元数据时从原生文字层估计正文主字号。同一页、同一缩放下，正文、列表和表格使用统一字号，取英文正文的 94%，且至少 14px，行距为 1.5。标题至少为正文的 1.22 倍，图注为正文的 83% 且至少 12px。不逐段缩小以挤入来源高度。段落起点按来源位置安排；译文过长时顺延后续中文区块并增高页面，不裁切译文，也不移动原 PDF 英文文本层、画布或批注。段落对齐是尽力匹配，不是逐行复刻或所有 PDF 的保证。

滚动模式下，原生阅读区域宽度小于 560px 时，在同一页面 iframe 内改为原 PDF 在上、中文在下；组合页高包含两者。原生页面容器以 720px × 当前请求缩放比例安排宽度，PDF 等比适配其中，使用原生横向滚动查看，现有缩放控件仍可调整大小。中文按来源顺序排版，宽度适配可见区域并跟随横向滚动保持可见；原生滚动条出现后会重新测量可见宽度，此模式不做段落起点的左右对齐。恢复宽屏后回到左右布局。

## 整本任务与原书伴随包

原生“阅读选项” → “翻译与双语” → “整本翻译…”及 PDF 书架右键菜单 → “整本翻译…”
打开同一个对话框。首次仍需提取原 PDF；对话框显示新章节使用的模型、整本状态、当前章节、
已完成章数、已审校段数、章节列表及“已译章节表格：x / y 页已恢复”，提供开始、暂停、继续、
“恢复已有译文表格”及“导出双语包（当前进度）”。表格进度只统计正文全部审校通过的章节内
已检测表格页；每页无论有几个表格，都只计一页。
它沿用原菜单主题与既有控件，不新增独立阅读器或第二个书架条目。

`BookQueue` 将整本任务持久化到 `book_tasks`，由现有单一章节 consumer 按目录顺序推进。
完成的章节复用原正文及模型；旧章节若缺少已检测表格页映射，会先重新排队补齐，再向后推进。
新建章节使用整本任务模型，已存在的未完成章节保留
原模型、输入和阶段状态。无可翻译文字的章节不发起翻译。暂停作用于整本及当前章节，关闭
对话框或页面不会暂停任务；服务重启后继续未完成任务，主动暂停仍保持暂停。失败、额度
不足和 `needs_review` 停止后续章节推进；待复核内容不会被整本继续操作静默覆盖。
全部可翻译章节及其已检测表格页完成后，后台自动生成私有 `books/<book-id>/bilingual.koodo.zip`。

手动导出通过 `POST /api/translation/books/<book-id>/export` 获取当前进度包，不调用模型，
不自动恢复尚未处理的格式。当前仅有导出，没有双语包导入或在原生阅读器中直接打开该 ZIP
的界面。浏览器书库继续保留原书；笔记与高亮需通过原阅读器已有备份功能保存。

### 书架译文标识

`GET /api/translation/library` 批量返回书库别名键对应的已审校段数、总段数及整本完成状态，
不载入完整 Agent 产物，也不创建任务或生成导出文件。同一源书的多个别名共享译文状态。
只有已完成作业中存在 accepted 段落时才有标识；提取完成或仅有初稿不等于存在已审校译本。
“有译文”表示可导出当前进度；“已全译”要求全部可翻译章节完成且已审校段数与总数一致，
也覆盖逐章手动译完、尚未创建整本任务的书。

`TranslationLibraryProvider` 在书架共享一次请求，每 10 秒、窗口聚焦、页面重新可见及翻译
更新事件刷新；卸载时中止请求和计时器。服务暂时不可用时保留最后已知状态，不影响原生书架。
卡片封面右上角显示蓝色“有译文”或绿色“已全译”，详情和列表显示同名标识。标识有进度说明、
键盘焦点与按钮语义；点击时阻止父级导航/多选，打开原有整本任务窗口，继续使用现有导出功能。

### 双语包版本 1

这是原书的伴随归档，ZIP 内包含：

| 路径 | 内容 |
| --- | --- |
| `manifest.json` | `format=koodo-bilingual`、`version=1`、书籍与来源标识、英中语言、章节、读取签名、`completed` 或 `partial` 状态、按页统计的 `table_presentation` |
| `source.pdf` | 原始 PDF 的完整字节；封面引用为 `{source: "source.pdf", page: 1}` |
| `document.json` | 原提取文档，保留来源区块 ID、页码及坐标 |
| `chapters/<chapter-id>.json` | 当前分章内容、译文状态与段落定位信息 |
| `source-format-v1.json`、`page-format-NNNN.json`（存在时） | 已有来源格式及逐页译文格式映射 |
| `source-structure-v1.json`、`source-math-v1.json`、`layout-overrides-v1.json`（存在时） | 来源结构、本地数学识别与已验证的视觉分组元数据 |

不包含凭据、SQLite 数据库、Agent 私有任务输入或完整审校过程；格式文件中的 `job_id` 也被
去除。原区块 ID、译文文字偏移不变，但包不包含原生笔记与高亮备份。未完成章节仍随当前
状态导出，不能把 `partial` 包当成已完成全书。manifest 只有在全部可翻译正文及所有已检测表格页
映射均就绪时才为 `completed`；`table_presentation.total` 与 `completed` 统计全书表格页数，
范围包含尚未翻译的章节，与窗口仅统计已审校章节的表格进度不同。

### 阅读快照与失效

`PublicationStore` 先读取签名匹配的包内章节，再读取私有 `reading-<chapter-id>.json` 快照，
必要时从当前任务数据重建。当前读取签名版本为 5，使旧派生 ZIP 和阅读快照失效一次，
重新读取可反映来源结构、数学识别、视觉分组及表格就绪状态；不改变原文或已审校译文。SQLite 仍是运行、恢复与状态的权威存储；读取签名仍查询本地
章节/作业修订号，不表示阅读完全脱离数据库。签名还包含 `document.json`、来源格式、
`source-structure-v1.json`、`source-math-v1.json`、`layout-overrides-v1.json` 及逐页格式文件的时间戳与长度。每次任务或作业更新递增修订号，因此等长译文更新也能使旧快照失效；
服务重启将运行中的章节重排为 `queued` 时同样递增修订号。损坏的派生 ZIP 或快照回退到当前
任务数据，不遮蔽已有结果。构建期间若签名变化，不缓存过期内容；导出检查各章节前后签名，
持续更新时提示稍后重试，已有结果保留。进度计算批量读取作业状态，避免逐章装载完整产物。

### 原封面显示

双语模式下，PDF 物理第 1 页只有一个覆盖整页的图片区块时，中文侧复制现有原生 PDF canvas
的完整 backing pixels，并沿用其 CSS 显示宽度和偏移；不走裁剪缩略图、不重新编码封面，
也不添加封面标题或留白。未符合条件时沿用普通页面路径。书架原有封面提取逻辑不变。

## 已有译文的格式恢复

后台从原 PDF 提取加粗、斜体、等宽/衬线文字和表格几何，保存为书籍目录中的附加 `source-format-v1.json`；每页的译文格式映射保存为 `page-format-NNNN.json`。原 `document.json`、书籍 ID、提取版本、来源区块 ID 和源 PDF 均不变。

章节正文全部审校通过后，`ChapterQueue` 自动为该章每个已检测表格页恢复映射，全部就绪才标记章节 `completed`。格式阶段仍使用同一章节任务、原批次、原模型和同一生产 consumer；失败、额度不足、暂停或服务重启后使用既有章节继续流程，并复用持久化的逐页格式作业指针，跳过已为 `ready` 的页面。面板通过 `phase=formatting` 区分正文已完成、等待恢复表格、正在恢复及恢复中断，已审校段数不会退回未翻译。

旧译文可在整本窗口点击“恢复已有译文表格”，调用 `POST /api/translation/books/{book_id}/tables/repair`。接口只把正文全部审校通过且有待恢复表格页的章节重新排队，不创建整本翻译任务，也不重译正文；格式 Agent 沿用原章节的订阅模型对齐现有中文。无表格、仅需恢复字体样式的页面仍由“恢复本页格式”手动处理。整本协调器也会在跳过旧的 `completed` 章节前检查缺失的表格映射。

格式 Agent 使用本应用自己的订阅授权及 OpenAI Agents SDK，只从已有中文中返回精确引文及其出现次数。程序验证来源标识、允许的区块、完整单元格集合与文字覆盖，拒绝改写、遗漏、重叠或引用其他单元格的区块，再转换为 UTF-16 偏移。来源格式与现有译文共同构成指纹；章节读取时若指纹变化，旧格式返回 `pending`，不把旧格式套到新文字上。完整结果可直接复用；映射尚未恢复或表格片段未完整覆盖文字时，前端回退到普通译文。页头按章节状态显示“表格结构待恢复”“表格结构恢复中”或“表格结构恢复失败”；重试操作发出既有翻译更新事件，立即刷新已挂载阅读器，渲染签名包含任务状态，避免沿用过期失败文字。

前端生成语义 DOM：加粗为 `strong`，斜体为 `em`，等宽为 `code`，衬线为带字体样式的片段；表格使用 `table`、`th`、`td`，保持来源行列和跨行跨列信息。模型不生成 HTML 或新增文字。来源相邻单行正文可合为一个视觉段落，各片段仍保留原区块 ID 和精确译文；不改写或增补正文来修正原提取方式。

格式任务与章节翻译共享生产 worker 的 `operation_lock` 和私有目录 `worker.lock`。调用模型前先持久化格式任务指针；恢复可复用已完成的格式阶段，不再发起模型请求。不得另起一个生产 worker 访问同一状态目录。响应尚未持久化即崩溃时仍可能重发该阶段，不承诺计费层面恰好一次。

## 来源代码、公式与提示框

私有书籍目录的附加 `source-structure-v1.json` 当前内容版本为 3。它从原 PDF 的来源行、等宽字体标记及 `SourceCodePro` 等字体名、代码语法和版面推导逐页代码、行内公式与提示框信息；不改写源 PDF、`document.json` 或既有 accepted 产物。检测为代码的来源 ID 在读取与规划视图中按代码处理，从新建翻译/审校批次、可翻译段数及已审校正文统计中排除。代码块中的注释、字符串、输出与代码本身一律保留原文，不进行中文翻译。旧作业记录与输入保持冻结。含新识别代码的未完成批次改建为只含正文的新作业，旧记录与产物仍保留；其余旧作业使用原输入恢复，旧完成作业直接复用。

前端在 `pre`/`code` 中按来源行重建缩进、空行和换行，保留原始代码文字；代码内部横向滚动，不通过自动折行破坏结构。左侧 PDF 仍保留原语法颜色，右侧当前为纯色等宽文本。旧提取跨页合并的公式与代码仅在展示层拆分到实际来源页；片段保留原规范区块 ID、精确文字与 UTF-16 起止偏移，支持旧中文文字锚点跨片段定位。原提取未收录的代码行使用稳定派生 ID，仅作为来源展示，不加入翻译正文或修改原始提取文件。

行内公式作为受保护来源字面量归属于正文。格式模型只接收既有中文及非代码的来源样式、表格和公式元数据，通过精确引文锚点指定插入位置；程序验证后生成 UTF-16 偏移，模型不改写中文。未就绪时保留可见的来源公式回退。提示框使用实际图标裁片和对应既有中文，避免含英文正文的整张截图与中文重复；与矢量表格重叠的底图被排除出提示框处理，表格仍使用原单元格渲染路径。

这是一套来源识别启发式，没有 OCR，也不保证任意 PDF 的代码、公式或提示框都能识别。代码原文与其旧锚点可以同时保留，但不会将不再对应当前可见文字的旧引文强行恢复到错误位置。笔记、选中菜单与编辑器继续委托原生路径，未迁移用户笔记数据库。

## 完整逻辑区块的排版识别

原生“阅读选项” → “翻译与双语”内提供“重新识别排版”，由 `LayoutControls` 显示排队、当前检查页范围、完成、待确认或失败状态。任务在后台执行，可继续阅读；手动操作在上一任务结束后仍可重新运行。`GET /api/translation/books/{book_id}/layout?page=N` 读取该页最近任务，`POST` 接收 `page`、`model` 及可选的 `automatic`。只有已提取书籍使用该入口。

`layout_sources.py` 直接从原 PDF 生成来源行 ID、原文字面量、物理页、坐标及字体信息。明确且完整的多行数学结构先由本地规则归组；公式歧义、相邻页的代码延续边界进入视觉路径。新章节翻译前审计整章来源页，侧栏开启双语时也可触发当前页的自动检查。自动任务按原 PDF 的 `source_hash` 与规则 `VERSION` 缓存，复用已覆盖该页范围的结果；未解决的同签名结果也不会自动反复调用模型，用户可手动重试。自动识别失败或待确认时，该章以 `layout_requires_confirmation` 停止向后翻译，已有译文继续保留。

视觉任务从当前页及前后各一页开始，将原 PDF 页面截图和来源行/坐标交给同一 OpenAI Agents SDK 与应用订阅模型。结构化输出仅含 `formula`、`code`、`paragraph` 的来源行引用、前后扩展标记和不确定标记；不生成 LaTeX、HTML、翻译或改写文字。代码包含原注释和输出，公式符号保持原样；图像和书内文字视为待识别数据。

程序校验来源行存在、唯一、顺序及连续页范围，要求所选规范来源区块的行完整覆盖，也检查旧分组的完整边界。模型或规范区块显示边界未闭合时，每次向相应方向扩展两页，重新检查完整窗口；公式和代码可跨物理页及章节边界，段落只能组合单页的完整规范区块。最多 18 个上下文页、10 轮；结构校验失败可带错误信息重试一次。仍有歧义、边界超限或重试失败则为 `needs_confirmation`，保留此前布局，不写入局部识别结果。表格、图像和提示框不进入此分组，继续沿用专用路径；不支持的结构可保留待确认。

`layout_tasks` 持久化在同一 SQLite，运行任务重启后重新排队；与章节和格式任务共用 `operation_lock`、`worker.lock` 及单一 consumer，不启动第二个生产 worker、不读取 Codex 凭据或回退 API Key。本地规则缓存为私有 `source-math-v1.json`，完整验证的视觉分组经原子替换写入 `layout-overrides-v1.json`；源 PDF 和 `document.json` 不变。模型已返回、尚未持久化时崩溃仍可能重发，不承诺计费层面恰好一次。

前端按来源行展示代码，公式使用原 Unicode、来源坐标行偏移和数学回退字体（Cambria Math、STIX Two Math、Times New Roman），不保证复刻嵌入 Type3 字体或任意分式排版。完整段落分组复用 accepted 中文及原有加粗、行内公式锚点。规范区块 ID、UTF-16 笔记定位和旧派生代码别名保留；新增来源行 ID 独立于分组，不迁移旧笔记。阅读快照与伴随包包含这些附加展示元数据，导出移除私有作业 ID；不包含 `layout_tasks` 数据库或模型私有输入。

## 目录条目与印刷页码

来源目录元数据 `toc_entries` 由原区块文字和坐标派生：同页至少三条具有重复点状引导线、共同页码
右边缘的条目才识别为目录，支持数字和罗马数字。记录来源区块 ID、标题、印刷页码、相对缩进及
标题/页码加粗。每次来源格式读取也为旧缓存页派生这些信息，不修改原 `document.json`。目录元数据
不参与已有格式指纹或格式 Agent 输入，已缓存的加粗及表格映射可继续复用；前端排除包含目录
区块的旧正文合并组，防止多个条目再次粘成一段。修正已有目录显示不需要模型请求。

中文条目使用标题、引导线、页码三个连续的 UTF-16 片段，保留缓存中文的全部字符、原区块 ID 和
偏移。字面点线或制表符保留为零字号文字，由 CSS 点状边框随剩余宽度伸缩；标题可换行，末尾
页码列宽 `3ch`、右对齐并使用等宽数字。缩进随源页比例缩放，最多占中文可用宽度的 20%；标题
与页码保留各自来源加粗信息。宽窄屏都按独立条目排列，长标题换行后页码位于该条目末行右侧。
印刷页码不换算为 PDF 物理页索引，例如印刷 9 仍显示 9，不改成物理第 11 页。若译文末尾无法
匹配来源的印刷页码，回退普通译文。旧笔记可跨标题、原字面点线和页码恢复，无需迁移数据库。

## 多段合批与恢复

原章节工作流已按最多 12 段、6,000 源字符合批，输入 schema 最多 20 段，并非逐目录行请求。
当前 `BatchBudget` 默认最多 96 段、20,000 源字符，同时用 UTF-8 字节估算输入、输出和审校上下文：
输入预算 6,000 tokens（包含共享提示、schema、工具与术语的 1,500 tokens 预留），输出预算
6,000 tokens，审校预算 14,000 tokens。估算不是模型专用 tokenizer，也不保证实际模型上下文上限；
不可再分的旧区块超过软估算时独占一批，仍受 20,000 源字符输入硬限制。

识别为目录的条目仅在模型输入中去掉重复字面引导线，改为 `标题\t印刷页码`，保护最后的制表符及
页码。已有受保护字面量无法保留时使用原文。原提取文字、来源 ID、译文缓存身份和已创建作业的
输入不变。新批次以 `source_mode=compact-toc-v1` 持久化此策略；恢复时仅重新合并连续且尚未创建
`job_id` 的批次，已经开始或失败待重试的作业继续使用原输入和指纹。

每批仍执行翻译、独立审校及必要修订；工具回合会产生额外模型请求，工作流批次并不等于请求数。
面板的 `batch_count`、`completed_batches` 显示批次进度，与已审校段落进度分别计算。

## 批注兼容

英文 `getHighlightCoords`、`createOneNote` 和 `renderHighlighters` 直接委托原生实现。中文选区保存为 `koodo-pdf-translation-v1`，包含书籍提取指纹、原 PDF 页索引、段落 ID、文字偏移与引文。恢复时同时校验书籍身份和引文，避免译文变化后错位。每个格式片段携带 `data-translation-start` 的 UTF-16 起始偏移；同一旧区块分布到多个表格单元格后，旧 `koodo-pdf-translation-v1` 范围仍能跨片段恢复，无需笔记数据库迁移。两种范围分开渲染，但均使用原生笔记数据库、编辑器、标签和删除流程。

## 生命周期

原生 PdfRender 会在长期存在的 `#page-area` 上添加滚动监听器。开关双语、缩放或重建时，适配器清理旧监听器、轮询和 ResizeObserver，并阻止旧渲染器延迟回调覆盖新页码。DOM 回归测试覆盖这个问题。`removeContent` 仍由原生实现清空内容。

任务与译文使用原有 `/api/translation/` 和私有状态目录，格式恢复只添加展示信息，不重译现有正文；自动恢复与旧表格补齐会更新原章节任务的排队、运行、完成状态及修订号，原翻译作业与批次输入保持不变。译文轮询更新已载入的活动章节及仍有待恢复表格的旧完成章节，并在用户选中中文时延后替换，避免破坏选区。

收起“翻译与双语”会卸载任务控件并清理其轮询；再次展开时读取当前章节和后台任务状态。此操作不改写双语开关，不卸载 `Viewer`，也不暂停后台任务；任务暂停仍使用“暂停翻译”。关闭右侧阅读选项沿用原生侧栏的显示行为。
